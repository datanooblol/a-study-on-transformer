Attention & RoPE

Every block in this repo — encoder, decoder, GPT-decoder, the insurance variants — is built from the same two pieces: scaled dot-product multi-head attention, and RoPE for position. Learn these once.

Core concept — used by every architecture
Files to open alongside this lesson
  • package/encoder_block.py — RoPE, MultiHeadAttention
  • package/decoder_block.py — MaskedSelfAttention (adds the causal mask), CrossAttention (Q from one sequence, K/V from another)

Why attention at all

Before attention, sequence models (RNNs) squeezed an entire sequence through one hidden state, updated one token at a time — early tokens had to survive many updates to still matter by the end. Attention removes the bottleneck: every output position can directly look at every input position and decide, per pair, how much it matters. Nothing has to survive a relay race.

Q, K, V — three projections of the same token

Each token vector is projected three different ways, each with its own learned linear layer:

  • Query — "what am I looking for?" (from the token asking the question)
  • Key — "what do I contain?" (from every token being looked at, including itself)
  • Value — "what do I actually hand over?" once attention decides to look at me

Scaled dot-product attention

Similarity between a query and a key is a dot product. Divide by sqrt(head_dim) so the scores don't blow up as dimensionality grows, softmax to turn scores into weights that sum to 1 per row, then take a weighted sum of the values:

package/encoder_block.py — MultiHeadAttention.forward
scores = torch.matmul(q, k.transpose(-2, -1)) / (self.head_dim ** 0.5)

if mask is not None:
    scores = scores.masked_fill(mask[:, None, None, :], float("-inf"))

attn = scores.softmax(dim=-1)
out = torch.matmul(attn, v)
attention weights — one row per query token, columns are the keys it looked at (each row sums to 1.0)

Multi-head — several small attentions instead of one big one

d_model is split into n_heads chunks of head_dim = d_model // n_heads. Each head runs its own attention independently, in parallel, then the heads are concatenated back together. This lets different heads specialize — one might track "the previous policy purchased," another "how long ago."

package/encoder_block.py — MultiHeadAttention.forward
# (batch, seq_len, d_model) → (batch, seq_len, n_heads, head_dim)
q = self.q_proj(x).view(batch, seq_len, self.n_heads, self.head_dim)
...
# (batch, seq_len, n_heads, head_dim) → (batch, n_heads, seq_len, head_dim)
q = q.transpose(1, 2)
...
# after attention: merge heads back
out = out.transpose(1, 2).contiguous().view(batch, seq_len, d_model)
return self.out_proj(out)
💡 Tip

d_model must be divisible by n_heads — head_dim = d_model // n_heads with no remainder, or the reshape silently truncates. E.g. d_model=64, n_heads=4 → head_dim=16.

RoPE — position as a rotation, not an addition

The classic transformer adds a positional encoding vector to the input embedding before anything else happens. RoPE takes a different approach: it doesn't touch the input at all. Instead, it rotates the Q and K vectors — every consecutive pair of dimensions is treated as a 2D point and rotated by an angle proportional to the token's position:

package/encoder_block.py — RoPE
theta = 1.0 / (10000 ** (torch.arange(0, dim, 2).float() / dim))
positions = torch.arange(max_len).float()
angles = torch.outer(positions, theta)   # (max_len, dim//2) — angle per (position, dim-pair)

# ...in forward(): rotate each (x0, x1) pair by its angle
out0 = x0 * cos - x1 * sin
out1 = x0 * sin + x1 * cos

Each (x0, x1) pair in Q and K is spun around the origin by an angle that grows with both the token's position and which dimension-pair it is (early pairs rotate fast, later pairs rotate slow).

Why bother rotating instead of adding? Because when you later take the dot product of a rotated query and a rotated key, the absolute rotation angles cancel out and what survives is the difference in position between the two tokens. Attention ends up naturally position-aware in a relative sense — "3 tokens ago" means the same thing whether you're at position 10 or position 400 — without the model ever seeing an explicit distance number.

💡 Tip

RoPE is applied to Q and K only, never V. V carries content ("what to hand over"), not "where am I" — rotating it would scramble the information being passed along for no benefit.

Token 2 can see token 1 and itself, but not tokens 3 or 4 — this is what makes autoregressive generation trainable in parallel: every position's "predict the next token" target is masked to only see the past.

package/decoder_block.py — MaskedSelfAttention.forward
causal_mask = torch.ones(seq_len, seq_len, device=x.device).triu(diagonal=1).bool()
scores = scores.masked_fill(causal_mask[None, None, :, :], float("-inf"))

if pad_mask is not None:
    scores = scores.masked_fill(pad_mask[:, None, None, :], float("-inf"))

Both masks can — and in the decoder, do — apply at once: triu(diagonal=1) blocks the future, pad_mask blocks padding, and they're just two separate masked_fill calls stacked on the same score matrix.

⚠ Inconsistency / best practice

In every file above, mask/pad_mask means True = this position is PAD, mask it out. Later, in package/transformer.py (lesson 5), the same-looking mask argument means the opposite — True = real token, keep it — and gets inverted with ~mask before use. Both are internally consistent, but mixing them up when wiring a new dataset into one or the other will silently produce garbage attention with no error thrown. Always check which convention the specific attention class you're calling expects.

Checklist — what to remember

  • Attention = weighted average of Values, where the weights come from Query·Key similarity.
  • Multi-head = run several smaller attentions in parallel, concatenate, project back.
  • RoPE rotates Q/K by an angle proportional to position — never touches V.
  • Masking = set disallowed scores to -inf before softmax; padding masks columns, causal masks the upper triangle.
  • Watch the mask convention — True can mean "pad" or "real" depending on the file.
