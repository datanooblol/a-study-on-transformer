Three Architectures, One Building Block

BERT, the original "Attention Is All You Need" transformer, and GPT are not three different inventions. They're the same attention block from Lesson 1, wired together three different ways.

Encoder-only Encoder + Decoder Decoder-only (GPT)

1. Encoder-only — bidirectional, no generation

Every token attends freely to every other token, forward and backward. No causal mask. The output is one rich vector per input token, all built with full context. There's nothing autoregressive here — it doesn't generate anything, it understands the input.

input x (batch, src_len, d_model)
↓
Multi-Head Self-Attention every token sees every token
x = norm1(x + attn(x))
FeedForward
x = norm2(x + ffn(x))
output (batch, src_len, d_model) — one vector per token

Use cases: text classification, sentence embeddings, named entity recognition — anything where you're understanding/representing input rather than producing new sequence output. Real-world example: BERT — see Lesson 11 for how it's actually trained in two stages (pretraining, then fine-tuning).

2. Encoder + Decoder — transform one sequence into another

The encoder reads and compresses the source. The decoder generates the target one step at a time, but each decoder layer does two different attentions: masked self-attention over its own past output, then cross-attention where the decoder's Query looks at the encoder's Key/Value — this is the literal mechanism of "translating," deciding which part of the source to focus on for each output token.

Encoderreads src, full attention
⇒ enc_out
Decodergenerates tgt
decoder input x (batch, tgt_len, d_model)
↓
Masked Self-Attention only its own past tokens
x = norm1(x + masked_attn(x))
Cross-Attention Q from x, K/V from enc_out
x = norm2(x + cross_attn(x, enc_out))
FeedForward
x = norm3(x + ffn(x))
output (batch, tgt_len, d_model)
package/decoder_block.py — CrossAttention.forward (the key lines)
# Q comes from decoder (x), K and V come from encoder (enc_out) — the only
# structural difference from self-attention
q = self.q_proj(x).view(batch, tgt_len, self.n_heads, self.head_dim).transpose(1, 2)
k = self.k_proj(enc_out).view(batch, src_len, self.n_heads, self.head_dim).transpose(1, 2)
v = self.v_proj(enc_out).view(batch, src_len, self.n_heads, self.head_dim).transpose(1, 2)

# result is (batch, n_heads, tgt_len, src_len) — NOT square, because query and
# key sequences have different lengths (decoder's tgt_len vs encoder's src_len)
scores = torch.matmul(q, k.transpose(-2, -1)) / (self.head_dim ** 0.5)
💡 Tip

Cross-attention gets no RoPE in this codebase — Q and K come from two different sequences (target vs source), so "relative position between them" isn't a coherent idea the way it is within one sequence.

Use cases: machine translation, summarization, speech-to-text. Real-world example: the original Transformer paper, encoding English and decoding French.

3. Decoder-only (GPT-style) — causal, one sequence, no encoder

Same shape as the encoder block, but with a causal mask added — each token attends to itself and everything before it, never the future. There's no encoder and no cross-attention because there's nothing else to look at; the model only ever conditions on its own past.

input x (batch, seq_len, d_model)
↓
Masked Self-Attention causal — no cross-attention
x = norm1(x + attn(x))
FeedForward
x = norm2(x + ffn(x))
output (batch, seq_len, d_model) — position i built only from 0..i

Use cases: text generation, code completion, chat. Real-world example: GPT — stack many of these blocks, predict the next token from everything so far.

Structurally: EncoderBlock + a causal mask = GPTDecoderBlock. GPTDecoderBlock + a CrossAttention sub-layer (and its own norm) = DecoderBlock. That's the entire difference — same attention math, same feed-forward, same residual+LayerNorm pattern, three different masks and wiring choices.

✓ Pattern worth reusing

Before reaching for a new architecture, ask which of these three problems you actually have: "represent input" (encoder), "transform one sequence into a different one" (encoder-decoder), or "continue a sequence" (decoder-only). Nearly everything in NLP and beyond maps onto one of these three.
