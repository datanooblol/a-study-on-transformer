CLS Token & Padding Mask

The encoder outputs one vector per input token. But a regression/classification head needs exactly one vector per sequence. This lesson is about the trick that bridges that gap, and the mask that makes it work correctly on variable-length input.

Encoder-only
Files to open alongside this lesson
  • CLS_and_PAD.md — original deep-dive this lesson visualizes
  • train_insurance_representation_for_claim.py — SequenceEncoder (the real implementation)

Two problems, one section each

  1. How do you collapse a variable-length sequence into one fixed-size vector?
  2. How do you stop the model from attending to PAD positions that carry no real information?

CLS token solves problem 1. Padding mask solves problem 2. They're used together, but they're solving different things.

What gets built in __init__

SequenceEncoder.__init__
# +1 for PAD token at index 0 — padding_idx=0 keeps its embedding at all zeros
# and PyTorch never updates that row during training
self.embed = nn.Embedding(vocab_size + 1, d_model, padding_idx=0)

# one learnable CLS vector, shared across the whole batch — starts random,
# gradually learns to be a good "collector" of sequence information
self.cls = nn.Parameter(torch.randn(1, 1, d_model))

# max_len + 1 because prepending CLS makes every sequence one token longer
self.encoder = EncoderBlock(d_model, n_heads, max_len + 1)

Forward, step by step

1. Build the padding mask

SequenceEncoder.forward
pad_mask = tokens == 0   # (batch, seq_len) — True = this position is padding

2. Prepend a False column for CLS

cls_col  = torch.zeros(batch, 1, dtype=torch.bool, device=tokens.device)
pad_mask = torch.cat([cls_col, pad_mask], dim=1)

CLS is never padding, so its column is always False — we add it purely so the mask's shape matches the sequence length after CLS is prepended in step 3.

3. Embed tokens and prepend CLS

x   = self.embed(tokens)              # (batch, seq_len, d_model)
cls = self.cls.expand(batch, -1, -1)  # (1, 1, d_model) → (batch, 1, d_model), no copy
x   = torch.cat([cls, x], dim=1)      # (batch, 1+seq_len, d_model)

4. Run the encoder

Every token attends to every other token (Lesson 1/2 — this is EncoderBlock, fully bidirectional), but PAD positions are masked to -inf so softmax gives them ~0 weight everywhere. CLS attends to every real token and pulls their information into its own output slot.

5. Read only the CLS output

out = self.encoder(x, pad_mask)   # (batch, 1+seq_len, d_model)
return out[:, 0]                  # (batch, d_model) — CLS position only

All five non-CLS outputs are computed but simply discarded — CLS* is the one fixed-size vector that summarizes this entire variable-length customer history.

Why CLS instead of averaging?

Averaging all real token vectors is a legitimate, simpler alternative:

return out[:, 1:].mean(dim=1)   # average over real positions only

CLS is generally preferred because averaging treats every token equally by construction, while CLS learns what to weight — it can learn "the most recent purchase matters more" if that's what the loss rewards. It's also the same trick BERT uses for sentence embeddings, so it's well-trodden ground — see Lesson 11 for how BERT actually trains this CLS vector to be useful in the first place, before any downstream task ever sees it.

💡 Tip

padding_idx=0 zeroing the PAD embedding is a nice-to-have, not the safety mechanism. The mask is what actually prevents PAD from influencing the result — without it, PAD's (zero) vector would still receive a nonzero softmax weight and get mixed into every other token's attention output.
