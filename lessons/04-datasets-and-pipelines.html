Constructing a Dataset

Real sequences don't arrive the same length. Before any attention math happens, you need a reliable way to turn a pile of variable-length sequences into equal-shaped batches, plus a mask that tells the model which positions are real.

Core concept — used by every architecture

  • package/pad_and_mask.py — pad_and_mask

The core problem

torch.utils.data.DataLoader needs every sample in a batch to stack into one tensor — which means equal shape. A Dataset that returns raw variable-length lists ([1,2,3], [4,5,6,7]) will crash the default collate function. You need to decide when padding happens: once, up front, or per-batch, right before the model sees it.

package/data_loader.py — InteractionDataset
class InteractionDataset(Dataset):
    def __init__(self, sequences: list[list[int]]):
        self.sequences = sequences   # stored as-is, no tensor conversion yet

    def __getitem__(self, idx):
        return self.sequences[idx]  # a plain list of ints, variable length

Two padding strategies

Option 1 — pre-pad in __init__Option 2 — pad in collate_fn
When padding happensonce, at dataset creationevery batch, to that batch's own max length
Wasted computehigher if one sequence is a huge outlier — everyone pads to the global maxlower — each batch only pads to its own longest sample
Code complexitysimpler — nothing extra at the DataLoader levelslightly more — a custom collate_fn
Growing datasetsfixed max length baked in — adding a longer sequence later needs a rebuildnaturally adapts, works with streaming data
Best forshort, similar-length sequences (e.g. this repo's insurance histories)widely varying lengths (e.g. 3 purchases vs 50)
Option 2 — collate_fn (from README.md)
def collate_fn(batch):
    policies, ages, prices = zip(*batch)
    policies_padded = torch.nn.utils.rnn.pad_sequence(policies, batch_first=True, padding_value=0)
    ...
    lengths  = torch.tensor([len(p) for p in policies])
    max_len  = policies_padded.shape[1]
    pad_mask = torch.arange(max_len).unsqueeze(0) >= lengths.unsqueeze(1)  # (batch, max_len)
    return policies_padded, ages_padded, prices_padded, pad_mask
✓ Pattern worth reusing

This repo's own applied projects (lessons 6–7) use Option 1 — customer purchase histories are short and similar in length, so the simplicity wins. Reach for Option 2 only once you actually observe wide length variance; don't build it preemptively.

The general-purpose version: pad_and_mask

Rather than writing a bespoke collate_fn per project, package/pad_and_mask.py factors the "pad to batch max + build a mask" logic into one reusable function:

package/pad_and_mask.py
def pad_and_mask(sequences: list[list[int]], pad_value: int = 0):
    lengths = [len(s) for s in sequences]
    max_len = max(lengths)

    padded = torch.full((len(sequences), max_len), pad_value, dtype=torch.long)
    mask   = torch.zeros(len(sequences), max_len, dtype=torch.bool)

    for i, seq in enumerate(sequences):
        padded[i, : lengths[i]] = torch.tensor(seq, dtype=torch.long)
        mask[i, : lengths[i]] = True   # True = real token here

    return padded, mask

⚠ Inconsistency / best practice — the mask convention, again

pad_and_mask returns True = real token. But encoder_block.py / decoder_block.py / gpt_decoder_block.py expect True = PAD in their mask argument (Lesson 1). Feed one straight into the other and every real token gets masked out instead of every PAD token — attention would collapse to garbage with zero errors or warnings. This repo's contrastive pipeline (Lesson 5) is built specifically around the pad_and_mask/"True=real" side and inverts internally (~mask) before it ever reaches attention — check which side any new code you write is on before wiring the two together.

Wiring it into a DataLoader

package/data_loader.py — create_dataloader
def create_dataloader(sequences, batch_size=32, shuffle=True, collate_fn=None):
    dataset = InteractionDataset(sequences)
    return DataLoader(dataset, batch_size=batch_size, shuffle=shuffle, collate_fn=collate_fn)

collate_fn is left pluggable on purpose — None uses PyTorch's default (fine for fixed-shape data), but this repo's contrastive pipeline (Lesson 5) passes a collate_fn that does far more than padding: it crops two random sub-sequences per sample before padding each group. That's covered next.

Checklist

  • Decide once: pad up front (simple, short/uniform sequences) or pad in collate_fn (adaptive, wide length variance).
  • pad_and_mask gives you both the padded tensor and the mask in one call — reuse it instead of re-deriving padding logic per project.
  • Know which mask convention (True=PAD vs True=real) the attention code on the other end expects — check, don't assume.
