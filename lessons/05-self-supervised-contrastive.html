Self-Supervised Contrastive Pretraining

No labels at all — just raw interaction sequences. This lesson learns useful embeddings by teaching the model that two random crops of the same sequence should look similar, and every other sequence in the batch should look different. This is SimCLR, applied to sequences instead of images.

The pretext task

Crop two random contiguous sub-sequences from the same source sequence — a positive pair. Every other sample in the batch (and its crop) becomes a negative. The loss pulls positive pairs' embeddings together and pushes negatives apart. No human-labeled target required.

package/collate.py — crop_pair
def crop_pair(sequence, min_len=3, max_len=None):
    def _random_crop():
        length = random.randint(min_len, max_len)
        start  = random.randint(0, n - length)
        return sequence[start : start + length]   # contiguous, order preserved

    return _random_crop(), _random_crop()   # two independent crops of the same sequence

NT-Xent — turning "closer/farther" into a loss

SimCLR's loss (Normalized Temperature-scaled Cross-Entropy). With batch size N, you get 2N embeddings total (N from crop 1, N from crop 2). Stack them, compute all pairwise cosine similarities (a 2N×2N matrix), mask out the diagonal (a sample is never compared to itself), and treat each row as a classification problem: "which of the other 2N−1 vectors is my actual positive pair?"

package/contrastive_loss.py — nt_xent_loss
z = torch.cat([z1, z2], dim=0)              # (2N, proj_dim) — z1 at 0..N-1, z2 at N..2N-1
sim = (z @ z.T) / temperature                # (2N, 2N) cosine similarity (z is L2-normalized)

mask = ~torch.eye(2 * N, dtype=torch.bool, device=z.device)
sim = sim.masked_fill(~mask, float("-inf"))  # exclude self-similarity

labels = torch.cat([torch.arange(N, 2 * N), torch.arange(N)], dim=0)
return F.cross_entropy(sim, labels)

Two entry points on the same model

ContrastiveTransformerEncoder deliberately exposes two different forward paths:

MethodUsed forReturns
forward(x, mask)training, feeds nt_xent_loss(batch, proj_dim) — through the projection head, L2-normalized
encode(x, mask)inference / clustering / similarity search(batch, d_model) — richer, pre-projection representation
package/transformer.py
def encode(self, x, mask=None):
    x = self.embedding(x)
    for layer in self.layers:
        x = layer(x, self.freqs, mask)
    x = self.norm(x)
    # mean pool over real tokens only (mask: True = real, matching pad_and_mask)
    x = (x * mask.unsqueeze(-1)).sum(dim=1) / mask.sum(dim=1, keepdim=True)
    return x

def forward(self, x, mask=None):
    x = self.encode(x, mask)
    x = self.proj_head(x)          # d_model → proj_dim, only needed for the contrastive loss
    return F.normalize(x, dim=-1)  # unit length so dot product = cosine similarity

The projection head is discarded after training — it's a scaffold that helps the loss, not part of the representation you actually want to keep. This is standard practice in contrastive learning (SimCLR found the pre-projection layer transfers better to downstream tasks than the projected space it was trained in).

⚠ Inconsistency / best practice — pre-norm vs post-norm

package/transformer.py's EncoderBlock normalizes before each sub-layer (x = x + dropout(attn(norm1(x))) — "pre-norm"), while package/encoder_block.py's EncoderBlock (Lessons 1–3, 6–7) normalizes after (x = norm1(x + attn(x)) — "post-norm"). Both are legitimate, widely-used transformer variants — pre-norm tends to train more stably at depth, post-norm was the original 2017 paper's choice — but this repo uses one for the contrastive pipeline and the other everywhere else. Worth knowing which one you're reading before assuming they're interchangeable line-for-line.

⚠ Inconsistency / best practice — no persistence in main.py, no validation anywhere

main.py trains and plots in one run; it never calls torch.save. The only working save/load round-trip in this repo lives in the scratch notebook dev.ipynb: torch.save(model.state_dict(), "model.pt") then model.load_state_dict(torch.load("model.pt")). Also — like the two applied projects in Lessons 6–7 — there's no train/val split here, so "the loss went down" is the only signal you get that pretraining worked. Lesson 8 covers concretely how to close both gaps.
