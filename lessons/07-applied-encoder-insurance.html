Applied Project: Claim-Amount Regression

Three different sequence types (purchases, claims, payments) plus a static profile, fused into one customer vector via three independent CLS-pooled encoders, to predict a single number: next year's claim amount.

Encoder-only
Files to open alongside this lesson
  • train_insurance_representation_for_claim.py — SequenceEncoder, InsuranceEncoderModel
  • CLS_and_PAD.md — the CLS mechanism itself (Lesson 3 covers this in depth)

One encoder per sequence type

Purchases, claims, and payments are different vocabularies with different meanings and different lengths (MAX_PURCHASES=5, MAX_CLAIMS=5, MAX_PAYMENTS=8) — so each gets its own SequenceEncoder instance, each with its own embedding table and its own learnable CLS token (Lesson 3). Age and income are just two numbers, so they get one small linear projection instead.

train_insurance_representation_for_claim.py — InsuranceEncoderModel.forward
purchase_vec = self.purchase_encoder(purchases)   # (batch, d_model)
claim_vec    = self.claim_encoder(claims)          # (batch, d_model)
payment_vec  = self.payment_encoder(payments)      # (batch, d_model)
profile_vec  = self.profile_proj(profile)          # (batch, d_model//2)

customer = torch.cat([purchase_vec, claim_vec, payment_vec, profile_vec], dim=1)
return self.head(customer)                         # (batch, 1)

Notice this is the same "fuse several feature sources into one vector" idea as EventEmbedding in Lesson 6 — the difference is Lesson 6 sums features that describe one event, while here we concatenate summary vectors that each already represent a whole (different-length, different-vocabulary) sequence. Sum when the pieces share a space and should blend; concatenate when they're genuinely different kinds of information the head should be free to weight independently.

Normalizer — three independent fits

train_insurance_representation_for_claim.py — train()
profiles = torch.stack([s[3] for s in dataset])   # (n, 2) — age, income
age_normalizer.fit(profiles[:, 0])
income_normalizer.fit(profiles[:, 1])
claim_normalizer.fit(all_claims)

Same discipline as Lesson 6: fit once on the training set, reuse for every transform and the final inverse_transform at inference.

claim_amount is its own stored value here, not a slice of purchases/claims/payments — it needs its own claim_normalizer for exactly that reason. Lesson 15 contrasts this "explicit target" pattern with Lesson 6's "derived" one, and a real bug that came from mixing the two up.

⚠ Inconsistency / best practice — dead code

Right above the snippet shown, train() also computes all_ages = torch.stack([s[3] for s in dataset]) and all_incomes = torch.stack([s[3] for s in dataset]) — both grab index 3 (the full 2-element profile tensor, age and income together), and neither is ever used again; the actual fitting happens on profiles[:, 0] / profiles[:, 1], computed separately right after. This is harmless (no bug — the correct values are fit), but it's leftover/redundant code: a good reminder to double check that a variable is actually consumed before assuming it's doing something.

Inference

train_insurance_representation_for_claim.py — predict()
pred_norm = model(purchase_ids, claim_ids, payment_ids, profile_norm)
pred_claim = claim_normalizer.inverse_transform(pred_norm[0]).item()

One forward pass, one number out — no autoregressive loop needed, because this model was never designed to generate a sequence, only to summarize one into a single prediction.

Checklist

  • Different sequence types (different vocab, different length) each get their own encoder + CLS — don't force them to share an embedding table.
  • Concatenate independent summary vectors when the head should learn to weight each source separately; sum when fusing features of one entity (Lesson 6).
  • Every regression target still needs its own Normalizer, fit once, reused consistently.
