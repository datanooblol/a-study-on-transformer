1. Time-series forecasting — the exact same causal pattern as Lesson 6 Decoder-only

Replace "purchase event" with "timestep." Replace policy/age/price with whatever continuous readings you're forecasting. The causal mask, the shift-by-one target, the "read the last position" inference — none of that changes.

sketch — forecasting sensor readings
class TimestepEmbedding(nn.Module):
    """Analogous to EventEmbedding in package/insurance_decoder_block.py — just no categorical part."""
    def __init__(self, num_features: int, d_model: int):
        super().__init__()
        self.proj = nn.Linear(num_features, d_model)

    def forward(self, features):        # (batch, seq_len, num_features)
        return self.proj(features)      # (batch, seq_len, d_model)


class ForecastModel(nn.Module):
    def __init__(self, num_features, d_model, n_heads, max_len):
        super().__init__()
        self.embed   = TimestepEmbedding(num_features, d_model)
        self.decoder = GPTDecoderBlock(d_model, n_heads, max_len)   # unmodified import
        self.head    = nn.Linear(d_model, num_features)             # predict next timestep's readings

    def forward(self, x, pad_mask=None):
        x = self.embed(x)
        x = self.decoder(x, pad_mask)
        return self.head(x)             # position i predicts timestep i+1 — same shift-by-one as Lesson 6

Training loop, loss shifting, and inference (predict() reading the last position) all carry over from Lesson 6 essentially unchanged.

2. Tabular / multimodal fusion — a relabeling you've already seen Encoder-only

EventEmbedding (Lesson 6) and InsuranceEncoderModel (Lesson 7) are already doing tabular fusion — they just call the columns "policy," "age," "price." Two ways to generalize this to an arbitrary table:

  • Row-as-one-token (what this repo already does): embed each column, sum them into one vector per row — cheap, and correct when columns mostly contribute independently.
  • Row-as-a-sequence-of-columns: treat each column as its own token in a short sequence, and let a real EncoderBlock attend across columns — useful when columns interact in ways a simple sum can't capture (e.g. "price only matters combined with policy type").
sketch — columns as tokens, attending across a row
class TabularRowEncoder(nn.Module):
    def __init__(self, column_specs, d_model, n_heads):
        super().__init__()
        # column_specs: e.g. [("category", 5), ("continuous", None), ("continuous", None)]
        self.col_embeds = nn.ModuleList([
            nn.Embedding(n, d_model) if kind == "category" else nn.Linear(1, d_model)
            for kind, n in column_specs
        ])
        self.encoder = EncoderBlock(d_model, n_heads, max_len=len(column_specs))

    def forward(self, columns):   # columns: list of (batch,) or (batch,1) tensors, one per column
        tokens = torch.stack([emb(col) for emb, col in zip(self.col_embeds, columns)], dim=1)
        return self.encoder(tokens)   # (batch, num_columns, d_model) — attention across columns
💡 Tip

Columns don't have a natural left-to-right order the way a sentence or a purchase history does — RoPE's "relative position" story is weaker here. It still runs (each column just gets a fixed position index), but know that the positional signal is more of a fixed "column slot ID" than a meaningful notion of distance.

3. Vision Transformer — the encoder block, completely unmodified Encoder-only

Split an image into fixed-size patches, flatten each patch's pixels, project to d_model — now you have a sequence of "tokens" and can reuse package/encoder_block.py's EncoderBlock and Lesson 3's CLS trick exactly as written, with zero changes to either.

sketch — patches as tokens, CLS for classification
class PatchEmbedding(nn.Module):
    def __init__(self, patch_size, in_channels, d_model):
        super().__init__()
        # a strided conv is just "linearly project each non-overlapping patch" done efficiently
        self.proj = nn.Conv2d(in_channels, d_model, kernel_size=patch_size, stride=patch_size)

    def forward(self, images):                    # (batch, C, H, W)
        x = self.proj(images)                     # (batch, d_model, H/patch, W/patch)
        return x.flatten(2).transpose(1, 2)       # (batch, num_patches, d_model)


class ViTClassifier(nn.Module):
    def __init__(self, patch_size, in_channels, d_model, n_heads, num_patches, num_classes):
        super().__init__()
        self.patch_embed = PatchEmbedding(patch_size, in_channels, d_model)
        self.cls         = nn.Parameter(torch.randn(1, 1, d_model))         # same idea as SequenceEncoder, Lesson 3
        self.encoder     = EncoderBlock(d_model, n_heads, num_patches + 1)  # unmodified import
        self.classifier  = nn.Linear(d_model, num_classes)

    def forward(self, images):
        x   = self.patch_embed(images)
        cls = self.cls.expand(images.shape[0], -1, -1)
        x   = torch.cat([cls, x], dim=1)
        x   = self.encoder(x)              # no padding mask needed — every image has the same patch count
        return self.classifier(x[:, 0])    # read CLS, exactly like Lesson 3

⚠ Inconsistency / best practice — RoPE assumes 1D order

Flattening a 2D grid of patches into a 1D sequence (row-major, in the sketch above) throws away the explicit 2D grid structure — patch 5 and patch 5+width-in-patches are vertically adjacent in the image but RoPE only encodes their distance along the flattened 1D sequence. Real Vision Transformers typically use 2D-aware positional schemes for exactly this reason. The sketch above still works and is a fair simplification for learning purposes — just know it's a simplification, not the state of the art.

The takeaway for this whole curriculum

Every lesson before this one taught mechanisms — attention, masking, RoPE, CLS pooling, padding, multi-task losses, contrastive pretraining, validation. None of those mechanisms know or care that the tokens happened to be insurance purchases. The only genuinely domain-specific code in this entire repo is the embedding layer at the very front (how you turn your raw data into a (batch, seq_len, d_model) tensor) and the head at the very back (how you turn a d_model vector back into an answer). Everything in between is the reusable part — and that's the actual thesis of this repo.
