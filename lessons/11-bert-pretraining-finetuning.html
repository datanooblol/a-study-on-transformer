What BERT actually is

BERT — Bidirectional Encoder Representations from Transformers — is, structurally, nothing new by the time you've read this curriculum: it's Lesson 2's encoder-only architecture (bidirectional self-attention, no causal mask), with Lesson 3's CLS token prepended for pooling. What made it a landmark model in 2018 wasn't a new block — it was a training recipe: pretrain once on unlabeled data, then fine-tune cheaply for any specific task.

Stage 1, part one — Masked Language Modeling (MLM)

Masked Language Modeling is a made-up task that needs zero human labeling: randomly hide about 15% of the input tokens behind a special [MASK] token, and train the model to predict what word was actually there — using the bidirectional context on both sides of the gap.

predict: "cat" — using both the left context ("The") and the right context ("sat on the mat") at once, which only a bidirectional encoder can do. A decoder (Lesson 2's causal architecture) could only ever see "The" and would have to guess blind.

The "label" for this task is just the word that was already sitting there before it got hidden — no human ever annotated anything. To predict it correctly, the model is forced to learn real grammar, semantics, and context, purely as a side effect of getting good at filling in blanks.

This is a genuinely different way of solving the same problem Lesson 6's decoder solves with a causal mask, and Lesson 7's encoder solves by storing a separate label — Lesson 15 puts all three side by side and explains exactly why hiding the input, rather than avoiding the setup entirely, is enough to keep bidirectional attention honest here.

💡 Tip — the 80/10/10 rule

Of the 15% of tokens chosen to be hidden, only 80% actually get replaced with the literal [MASK] token; 10% get replaced with a random other word, and 10% are left completely unchanged (but still graded as if hidden). Why bother: [MASK] never appears during fine-tuning or real use — only during this pretraining task. If every hidden position were always the literal [MASK] token, the model could get lazy and only build careful representations for positions that look like [MASK]. Mixing in random and unchanged tokens forces it to build good contextual representations for every position, since it can never be sure which ones are secretly being graded.

Stage 1, part two — Next Sentence Prediction (NSP)

Next Sentence Prediction is BERT's second pretraining task: feed it two sentences, A and B. Half the time, B genuinely is the sentence that followed A in the original text (label IsNext); half the time, B is a random sentence pulled from somewhere else entirely (label NotNext). The model reads this off the CLS token's final output, through a small binary classifier.

⚠ Worth knowing — later research revised this

NSP was part of the original 2018 BERT paper, but follow-up work (notably RoBERTa, 2019) found it contributed little and dropped it entirely, getting equal or better results training on MLM alone with more data and longer training instead. Good example of how even a well-known, influential design choice can turn out to matter less than assumed once someone actually runs the ablation.

The CLS token, defined

A quick, explicit definition since it's used constantly above: CLS ("classification token") is a special token prepended to the front of every input sequence. It doesn't correspond to any real word — its entire purpose is to attend to every other token in the sequence and accumulate a summary of the whole thing, which is then read off as one fixed-size vector for whatever classification or regression task sits on top. Lesson 3 already covers exactly how this mechanism works end-to-end (building the pad mask, prepending CLS, reading its output) — this lesson is just naming where that trick actually came from.

Stage 2 — fine-tuning for a downstream task

A downstream task is simply the actual thing you want to solve — sentiment analysis, question answering, whatever comes "downstream" of pretraining in the pipeline. Fine-tuning means: take the pretrained weights exactly as they are, attach one small task-specific head, and keep training — now supervised, now on a labeled dataset for that one task.

Downstream taskHow the pretrained model gets used
Sentiment classificationCLS's output → small linear layer → positive/negative
Named entity recognitionevery token's output (not just CLS) → linear layer → entity tag per token
Question answeringevery token's output → predict which token starts and which ends the answer span
Sentence-pair similarityCLS's output, computed over both sentences at once → a similarity score

Notice fine-tuning usually keeps training all of BERT's weights, not just the new head — the whole network keeps adjusting, just starting from a far better place than random initialization, and needing far less labeled data and far fewer steps to get there.

Why split training into two stages at all?

Labeled data is expensive and scarce — someone has to sit down and annotate it. Raw text is nearly free and effectively unlimited. Pretraining is what lets you extract everything learnable out of the cheap, abundant resource, so that fine-tuning only has to spend the expensive, scarce resource on specializing rather than learning language from zero. Skip pretraining, and every downstream task would need enough labeled data to teach a model general language understanding and the specific task — which most real tasks simply don't have enough labeled examples for.

✓ Where this shows up elsewhere in this curriculum

Lesson 5's contrastive pretraining is this repo's own version of Stage 1 — no next-item or multi-task labels needed, just a pretext task manufactured from the structure of the sequences themselves (two crops of the same sequence should look similar). The same two-stage question applies there too: it's worth it when labeled data is the bottleneck relative to how much raw sequence data you have — and not worth the extra complexity when it isn't.

Glossary

BERT
Bidirectional Encoder Representations from Transformers — an encoder-only Transformer (Lesson 2) that popularized pretrain-then-fine-tune for NLP.
Pretraining
Training on a task that needs no human-labeled data, usually on a huge corpus, to learn general-purpose representations before ever touching the task you actually care about.
Fine-tuning
Continuing to train an already-pretrained model on a smaller, labeled dataset for one specific downstream task.
Downstream task
The actual task you ultimately want solved (sentiment analysis, question answering, ...) — "downstream" because it comes after pretraining in the pipeline.
Self-supervised
A training signal manufactured from the structure of the data itself (e.g. "predict the word I just hid"), rather than from external human labels.
MLM (Masked Language Modeling)
BERT's main pretraining task — hide random tokens, predict the originals using bidirectional context.
[MASK] token
A special placeholder token used only during MLM pretraining to mark a hidden position; never appears during fine-tuning or real use.
NSP (Next Sentence Prediction)
BERT's second pretraining task — given two sentences, predict whether the second genuinely follows the first in the original text. Later found to add little value (see callout above).
[SEP] token
A separator token marking the boundary between two segments packed into one input (e.g. sentence A and sentence B in NSP).
CLS token
"Classification token" — prepended to every input, represents no real word, exists purely to aggregate sequence-level information via attention. See Lesson 3 for the full mechanism.
WordPiece (subword tokenization)
BERT doesn't tokenize whole words — rarer words get split into smaller subword pieces from a fixed vocabulary, so the vocabulary stays a manageable size while still covering essentially any word.

Checklist

  • BERT = Lesson 2's encoder-only architecture + Lesson 3's CLS pooling — no new block, a new training recipe.
  • Pretraining (MLM + NSP) needs zero labels, runs on massive raw text, and teaches general-purpose representations.
  • Fine-tuning starts from those pretrained weights and specializes on a small labeled dataset for one task.
  • The split exists because labeled data is scarce/expensive and raw text is abundant/cheap — pretraining spends the cheap resource, fine-tuning spends the expensive one sparingly.
  • Whether this two-stage approach is worth it for a project of your own comes down to one question: is labeled data actually your bottleneck?
