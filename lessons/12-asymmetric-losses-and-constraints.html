Asymmetric Losses & Hard Constraints

Not every wrong answer costs the same, and not every constraint should be left to the loss function to enforce. A ground-up look at two complementary tools — reshaping the loss, and reshaping what the model is even allowed to output — using next-purchase age prediction as the running example.

Core concept — applies to any regression head, any architecture
Related lessons to read alongside this one
  • Lesson 6 & Lesson 10 — where MSELoss is used as the default for every regression head so far
  • Lesson 8 — validation metrics, which should reflect the same asymmetry as the loss if one exists

This lesson isn't tied to a specific file in this repo — none of the applied projects currently need this, but the reasoning generalizes to any regression head you build on top of them later.

The problem: MSE doesn't know which direction is worse

Every regression head in this curriculum so far uses MSELoss or plain squared error — and MSE is symmetric: it penalizes predicting 5 units too high exactly the same as predicting 5 units too low. That's the right assumption most of the time. But not always.

Concrete case: predicting a customer's age at their next purchase. Age only moves in one direction — a customer's next purchase can never happen at a younger age than their current one. Predicting an age that's too high is a normal-sized mistake. Predicting an age that's too low, past what's physically possible, is a much bigger problem — not just "more wrong," but wrong in a way reality itself rules out. A symmetric loss has no way to express that difference.

symmetric loss (MSE) — same penalty either direction

Equal slope on both sides of zero — over-predicting and under-predicting by the same amount always cost the same.

Two different problems hiding inside one statement

"Age must be equal or more" is actually two separate claims bundled together, and they need two separate tools:

  1. A cost asymmetry — being wrong in one direction is more expensive than the other, but both directions remain possible. Fixed by reshaping the loss function.
  2. A hard constraint — one direction is not just costly, it's impossible. Fixed by reshaping what the model is allowed to output in the first place.

Ground up: solve the cost-asymmetry problem first (it's the more general one), then the hard-constraint problem, then see how they combine.

Tool 1 — Quantile (pinball) loss

MSE and MAE both optimize toward predicting the mean of a distribution. Quantile regression asks a different question: instead of "what's the average next age," it asks "give me a number I'm rarely below" (a high quantile) or "rarely above" (a low quantile). The tool that makes this work is the pinball loss (also called quantile loss):

pinball_loss.py
import torch

def pinball_loss(pred: torch.Tensor, target: torch.Tensor, q: float = 0.9) -> torch.Tensor:
    """q closer to 1 -> punishes under-prediction harder. q=0.5 -> plain MAE."""
    e = target - pred
    return torch.mean(torch.max(q * e, (q - 1) * e))

asymmetric loss (pinball, q = 0.9) — steep on one side, shallow on the other

Right side (under-prediction, e > 0) is steep — slope q = 0.9. Left side (over-prediction) is shallow — slope 1 − q = 0.1. Under-predicting the same amount now costs 9× more.

💡 Tip

q is a dial, not a fixed rule: q = 0.5 recovers plain symmetric MAE (equal slopes both sides). Push q toward 1 to make under-prediction increasingly expensive; push it toward 0 for the opposite. There's a second classic option worth knowing by name — Linex loss (exp(a·e) − a·e − 1) — which uses an exponential penalty on one side instead of a steeper line. Pinball loss is simpler to reason about and tune, so it's the better starting point.

Tool 2 — when "expensive" isn't enough: reparametrize the output

Here's the limit of Tool 1: even at q = 0.99, under-prediction is expensive, not impossible. A confused, undertrained network can still output an age below the true minimum — it just pays a large penalty when it does. For a constraint that's always true, not just usually costly to violate, reshaping the loss only discourages the mistake. What actually prevents it is changing what the model is mathematically allowed to produce.

Instead of predicting the next age directly, predict a non-negative increment from the age you already know, and add it back:

constrained_output.py
import torch.nn.functional as F

def predict_next_age(raw_output: torch.Tensor, current_age: torch.Tensor) -> torch.Tensor:
    """next_age_pred >= current_age is guaranteed by construction, not by training."""
    delta_age = F.softplus(raw_output)   # squashes any real number to a value >= 0
    return current_age + delta_age
softplus(x) = log(1 + exp(x)) — any real number in, always non-negative out

Even for a very negative raw output, the curve flattens toward (but never crosses) zero — it approaches the floor smoothly instead of hitting a wall.

⚠ Worth knowing — this is a general principle, not just an age trick

Whenever you know a hard fact about your output space ahead of time — a value must be non-negative, must stay inside [0, 1] (use sigmoid), must be one of a fixed set of categories, must sum to 1 across several outputs (use softmax) — it is almost always better to bake that fact into how you parametrize the output than to hope a loss function teaches the network to respect it on its own. A loss can only ever make violations expensive; a parametrization can make them mathematically unreachable.

Combining both

The two tools solve different problems and stack cleanly: reparametrize the output to make the impossible case unreachable, then optionally still shape the loss for whatever cost asymmetry remains among the physically valid outcomes.

combined.py
next_age_pred = predict_next_age(raw_head_output, current_age)   # Tool 2 — floor is guaranteed

loss_age = pinball_loss(next_age_pred, true_next_age, q=0.7)      # Tool 1 — mild remaining asymmetry

Notice q dropped from the earlier 0.9 to 0.7 here — with the hard floor already architecturally guaranteed, the loss no longer has to do the heavy lifting of preventing impossible predictions. It only needs to express whatever milder cost preference remains, if any. The two tools aren't fighting for the same job; each is doing the part the other can't.

Glossary

Symmetric loss
A loss (MSE, MAE) that penalizes over- and under-prediction of the same magnitude equally.
Asymmetric loss
A loss that penalizes one direction of error more than the other, on purpose, because the real-world cost of the two directions genuinely differs.
Quantile
A percentile of a distribution — "the value below which X% of outcomes fall." Predicting the 90th quantile means predicting a number you expect to be below only 10% of the time.
Pinball loss (quantile loss)
The loss function that trains a model to predict a specific quantile instead of the mean, by giving under- and over-prediction different slopes controlled by a parameter q.
Softplus
A smooth function, log(1 + exp(x)), that maps any real number to a non-negative one — used to guarantee an output can never go below zero, without a hard cutoff.
Reparametrization (of an output)
Changing what a model directly predicts (e.g. a bounded increment instead of an absolute value) so that a known constraint is satisfied automatically, rather than merely encouraged by the loss.
Hard constraint vs. cost asymmetry
A hard constraint means one outcome is truly impossible; a cost asymmetry means both outcomes are possible but one is more expensive. The first calls for reparametrizing the output; the second calls for reshaping the loss.

Checklist

  • Symmetric losses (MSE/MAE) assume both directions of error cost the same — true often, not always.
  • Pinball loss lets you dial in exactly how much more one direction should cost via a single parameter q.
  • If a direction is truly impossible, not just costly, reparametrize the output (softplus, sigmoid, softmax) so the model can't produce it at all.
  • The two tools compose — guarantee the hard floor architecturally, then shape the loss for whatever softer preference remains.
  • This generalizes past age: any output with a known floor, ceiling, or direction-dependent cost is a candidate for the same two questions.
