Proving Shift-by-One: One Pass, Not an Approximation

Lesson 6 introduced shift-by-one. Lesson 15 explained why causality makes it valid. This lesson proves it, with a script you can run yourself: one forward pass over a full sequence gives the exact same per-position results as running every truncated prefix separately — not an approximation, the same floating-point numbers — for a fraction of the compute.

Decoder-only (GPT-style) — this guarantee is specific to the causal case

The question this lesson answers

Take one customer's history, 8 events: [a, b, c, d, e, f, g, h]. You could imagine training on it two different ways:

  • Enumerate every prefix separately — x=[a], y=b, then x=[a,b], y=c, all the way to x=[a,...,g], y=h. Seven separate training rows.
  • One shift-by-one pass — x=[a,...,g], y=[b,...,h]. One row, seven positions supervised simultaneously.

Does the first one give you more to learn from? No — and this lesson shows exactly why, instead of just asserting it.

All seven enumerated rows are already sitting inside the single x=[a,...,g], y=[b,...,h] tensor — if position i's output genuinely only depends on positions 0..i. That "if" is exactly what needs proving, not assuming.

The two facts that make it true, not just plausible

  1. The causal mask. Position i is mathematically blocked from attending to any position after it — real or padded, doesn't matter (Lesson 1/2).
  2. RoPE depends only on absolute position. The rotation angle for position i is a function of i alone — never of how long the total sequence is. Position 2 rotates the same way whether it's the last position of a length-3 tensor or the third position of a length-8 one.

Together, these mean nothing about tokens after position i — whether they exist at all — can change position i's computed output. That's a stronger claim than "shift-by-one is a good approximation." It says the two computations are identical by construction.

In both views, c's output is built from exactly {a, b, c} — nothing else exists to attend to in the prefix view, and the causal mask makes sure nothing else is reachable in the full-sequence view. Same attended set, same weights, same output.

The runnable proof

Self-contained — needs only the decoder block you already import, nothing from your dataset or fusion code:

prove_shift_by_one.py
import torch
from package.gpt_decoder_block import GPTDecoderBlock

torch.manual_seed(0)

d_model, n_heads, max_len = 16, 4, 8
decoder = GPTDecoderBlock(d_model, n_heads, max_len)
decoder.eval()

# one sequence of 8 "events" — random vectors standing in for whatever
# FusionEmbedding would have produced. The values don't matter — only that the
# SAME decoder weights process them both ways below.
full_sequence = torch.randn(1, 8, d_model)

with torch.no_grad():
    full_out = decoder(full_sequence)   # ONE forward pass over all 8 positions at once

print(f"{'prefix':<10}{'last-pos idx':<14}{'identical?':<12}sample values (first 3 dims)")
for prefix_len in range(1, 9):
    prefix = full_sequence[:, :prefix_len]
    with torch.no_grad():
        prefix_out = decoder(prefix)     # a SEPARATE forward pass, just this prefix

    from_full   = full_out[:, prefix_len - 1]
    from_prefix = prefix_out[:, -1]
    same = torch.allclose(from_full, from_prefix, atol=1e-6)

    label = "abcdefgh"[:prefix_len]
    print(f"{label:<10}{prefix_len-1:<14}{str(same):<12}"
          f"full={from_full[0,:3].tolist()}  prefix={from_prefix[0,:3].tolist()}")

Every row should print True, and the full= / prefix= values on each row should be the exact same numbers, not just close. If you want to push on it: print (from_full - from_prefix).abs().max() instead of the boolean — it should be effectively 0, differing only by ordinary floating-point rounding, never by anything structural.

💡 Tip — the standard name for this technique

Training a causal model by feeding it the true previous tokens (not its own predictions) and computing loss at every position at once is called teacher forcing. It's the standard term you'll see in papers and other codebases for exactly what train_insurance.py's shift-by-one does — worth knowing the name, since "shift-by-one" describes the mechanics but "teacher forcing" is what people actually call the overall technique.

Why this matters: the efficiency isn't a minor detail

Enumerating prefixes separately doesn't just do redundant work — the redundancy gets proportionally worse the longer your sequences are. One full pass of length n costs roughly n² (attention is quadratic in sequence length). Enumerating costs 1² + 2² + ... + n² — because each shorter prefix pays its own full attention cost, recomputing positions it already computed as part of a shorter prefix moments ago.

The waste ratio grows roughly linearly with sequence length (it approaches n/3) — this isn't a fixed constant overhead you can shrug off, it gets worse the more history a customer has. Getting this right matters more, not less, as your sequences grow.

Where this guarantee stops applying

This is specific to the causal, per-position case — it is not a general property of every architecture. Lesson 15 already covers why: an encoder+CLS backbone has no causal mask (so the same slicing trick would leak the answer) and collapses the whole sequence into one vector before you get a prediction (so there's no per-position dimension left to slice from even if it didn't leak). Both failures are independent of what's proven here — this lesson's guarantee is real, but it only ever applied to the decoder path to begin with.

Glossary

Teacher forcing
Training an autoregressive model by feeding it the ground-truth previous tokens (not its own predictions) and computing loss at every position simultaneously — the standard name for what shift-by-one does.
Causal equivalence
The guarantee that a causal model's output at position i is identical whether computed as part of a longer sequence or from a truncated prefix ending at i — holds because of the causal mask plus position-only-dependent positional encoding.
Redundant computation
Recomputing the same result more than once — here, enumerating prefixes recomputes each early position's representation once per longer prefix that also contains it.

Checklist

  • One forward pass over a full sequence, under a causal mask, already contains every enumerated prefix's supervision — proven, not assumed.
  • The guarantee rests on two facts: the causal mask blocks the future, and RoPE's rotation depends only on absolute position.
  • The standard name for this training technique is teacher forcing.
  • Enumerating prefixes separately isn't just wasteful — the waste grows proportionally with sequence length, roughly n/3.
  • This guarantee is specific to causal, per-position architectures — it doesn't transfer to encoder+CLS, for the reasons Lesson 15 already covers.
