Visualizing Representations: What UMAP Confirms (and Reveals)

Lesson 17 gave us attribution deltas. Lesson 18 gave us R² and accuracy numbers. Both are correct and both are also easy to misread in the abstract. This lesson puts the same questions in front of your eyes instead: does the item embedding table group products the way the insurance catalog says it should? Does a customer's pooled representation actually look like it encodes age, the way Lesson 18's R²=0.70–0.95 claims? Visualizing mostly confirms what the numbers already said — except once, where it caught something the numbers alone didn't.

Both architectures — this lesson's examples use the encoder/concat_all config throughout

Three different things worth visualizing — and why they're not the same question

What's plottedWhat determines its shapeIs the shape a real discovery?
Item embedding tableAn unconstrained, freely learned lookup table (nn.Embedding)Yes — nothing forces any particular structure; whatever shows up is genuinely learned
Age / price / sum_insure projectionsA single nn.Linear(1, d_model) per featureNo — this is provably a straight line in d_model-dim space by construction; only direction and spread are learned, not "shape"

1. Item embedding table — does the model group products by insurance category?

The catalog groups 8 products into 5 categories (Term, WholeLife, Endowment, ILP, CriticalIllness). Nothing during training ever tells the model this grouping directly — if it shows up in the embedding geometry, it's because gradient descent found it useful, not because it was told to.

sequences_to_multiple_outcomes.ipynb (excerpt)
import umap

def get_item_embeddings(model):
    return model.backbone.fusion.categorical_embs[0].weight.detach().numpy()  # (num_items+1, d_model)

item_emb = get_item_embeddings(enc_model)
item_ids = list(range(1, num_items + 1))  # skip index 0 (padding)
item_vectors = item_emb[item_ids]

# only 8 points -- UMAP's neighbor graph isn't very meaningful at this scale;
# treat this as illustrative, not statistically rigorous
reducer = umap.UMAP(n_neighbors=4, random_state=55)
item_umap = reducer.fit_transform(item_vectors)

Result: only one of the three multi-item categories clustered the way the catalog predicts.

Strikingly, SmartTerm 20 sits closer to WealthBuilder Endowment (distance ≈0.8, a different category entirely) than to its own category-mate Term100 Protect. With only 8 points this isn't statistically strong evidence, but it's a real, specific, checkable pattern — not "no structure," but "not the catalog's structure."

✓ Pattern worth reusing — this ties directly back to Lesson 18's numbers

Item accuracy sat at chance level (~13–17%, vs. ~12.5% chance for 8 classes) for every config in Lesson 18. A model that barely learned to distinguish next-item identity at all shouldn't be expected to have organized its item embeddings around a clean semantic axis either — both observations point at the same underlying fact instead of being two unrelated coincidences. Cross-checking a probing result against an embedding visualization like this is a good habit generally: consistent stories across two independent methods are much more trustworthy than either alone.

2. Age / price / sum_insure projections — confirming the straight-line prediction

Each continuous feature goes through exactly one nn.Linear(1, d_model) — a scalar times a fixed direction vector, plus a constant offset. That is mathematically a single straight line through d_model-dimensional space, for any trained weights. There's no "shape" left to discover — only which direction the model picked, and how spread out along it the real value range ends up.

sequences_to_multiple_outcomes.ipynb (excerpt)
def sweep_continuous_projection(model, proj_index, values_norm):
    proj = model.backbone.fusion.continuous_projs[proj_index]
    x = torch.tensor(values_norm, dtype=torch.float).unsqueeze(-1)
    with torch.no_grad():
        return proj(x).numpy()

sweep_norm = np.linspace(-3, 3, 100)  # normalized units, ~full realistic range
age_vectors = sweep_continuous_projection(enc_model, 0, sweep_norm)
# ...same for price (index 1) and sum_insure (index 2)

from sklearn.decomposition import PCA
pca = PCA(n_components=2).fit(age_vectors)
print(pca.explained_variance_ratio_[0])  # expect ~1.0 -- confirms the single-line prediction

Result: all three swept projections, once run through UMAP, showed a smooth, continuously ordered curve — color transitioning cleanly from low to high value along one connected path, never scrambled or jumping around. That's exactly the confirmatory result the straight-line argument predicts. It's worth restating why this is confirmatory rather than novel: if the sweep had come out jumbled instead, that would have signaled a bug in the extraction code, not a discovery — the math guarantees the line before you ever run anything.

⚠ Inconsistency / gotcha — a color scale can manufacture "no signal"

The price plot's near-uniform dark color was ambiguous: with only 1–2 extreme high-price customers, a continuous color scale auto-ranges to fit them, compressing every other point into a narrow dark band — even if a real, weaker gradient existed among the non-outlier customers, this coloring would hide it entirely. Re-plotting with color=np.log1p(price) resolved this cleanly: the log scale revealed noticeably more color diversity across the plot (confirming real dynamic range had been hidden), but that diversity still didn't organize into a spatial trend the way age's did. That settles it two ways at once — the original flat-color read wasn't purely a plotting artifact, and price genuinely carries much weaker spatial structure than age, now checked on a fair scale instead of an outlier-compressed one.

What visualization actually added beyond the numbers

Worth being honest about which parts of this lesson taught something new and which just built confidence in what was already known:

  • New information: the item-embedding/category mismatch. Lesson 18 only tested whether the next item id was decodable — it never asked whether the embedding table's internal geometry respects the catalog's category labels. That's a genuinely different question, and the answer ("only partially") wasn't visible in any R² or accuracy number.
  • Confirmation, not new information: the customer-representation plots mostly reproduced what Lesson 18's R²/accuracy numbers already implied. Useful for building trust that the numbers mean what you think they mean — but not a new discovery on their own.
  • A transferable methodological lesson: the color-scale-outlier trap applies to any continuous-color visualization, not just this dataset — always sanity-check an apparently "flat" color plot with a log scale or percentile-clipped range before concluding there's no signal.

Glossary

Confirmatory vs. exploratory visualization
A confirmatory plot checks a prediction you already have a numeric answer for (like the customer representation plots here); an exploratory plot asks a question you don't have another answer to yet (like the item embedding table here). Both are useful, but only the second can genuinely surprise you.
Color-scale compression
When a small number of extreme values stretch a continuous color scale, visually flattening every other point into one indistinct band — checked by re-plotting with a log transform or a percentile-clipped color range before concluding "no signal" from a plot.
Provable vs. empirical structure
Some representations (a single nn.Linear(1, d_model) projection) have a shape that's mathematically guaranteed regardless of training — visualizing them is a sanity check, not a discovery. Others (a freely learned embedding table) have no such guarantee — visualizing them is a genuine empirical question.

Checklist

  • Know which kind of representation you're plotting before you interpret its shape — a learned lookup table's structure is a real finding; a single linear projection's structure is guaranteed by construction and only confirms what you already knew.
  • The item embedding table only weakly reflected the catalog's category structure (1 of 3 multi-item categories clustered cleanly) — consistent with, and explained by, Lesson 18's near-chance item accuracy.
  • Age, price, and sum_insure projections all showed the predicted smooth, ordered 1D curve — a confirmatory result, not a new one.
  • The customer-representation UMAP visually reproduced Lesson 18's R²/accuracy pattern almost exactly: clear gradient for age, scrambled for item, weak for price/sum_insure.
  • Before concluding "no signal" from a flat-looking continuous color plot, re-check with a log scale or percentile-clipped color range — a few outliers can visually erase real, weaker structure.
