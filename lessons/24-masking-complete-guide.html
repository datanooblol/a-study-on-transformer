Masking, Completely

Every earlier lesson used a mask without slowing down to build the whole mental model in one place — where it comes from, why -inf, why exactly one flip point, and how a single (batch, seq_len) boolean tensor reaches all the way into a 4D attention score matrix. The problem masking solves

Attention has no built-in notion of "this position is fake." scores = Q @ Kᵀ computes a real similarity number for every query-key pair — including pairs where the key is a padding position added purely to make a batch rectangular. Left alone, every real token's output gets blended with noise from padding.

💡 Tip — both can stack

package/decoder_block.py's MaskedSelfAttention applies both, as two separate masked_fill calls on the same score matrix — triu(diagonal=1) blocks the future, a padding mask blocks PAD. Order between the two calls doesn't matter; both just OR their blocked cells together onto the same tensor.

Why -inf before softmax, specifically

Softmax is exp(score_i) / sum(exp(all scores)). exp(-inf) = 0 exactly — so a masked score contributes nothing to the numerator for itself, and nothing to the denominator for anyone else. It vanishes completely, and the remaining real weights renormalize to sum to 1 automatically, with no manual rescaling required.

verify it yourself
scores = torch.tensor([2.0, 1.0, float("-inf")])
scores.softmax(dim=-1)
# tensor([0.7311, 0.2689, 0.0000])  -- real weights still sum to 1.0 exactly, masked position is exactly 0

Two consequences worth internalizing: masking must happen before softmax, not after — zeroing out a probability directly wouldn't renormalize the rest, leaving weights that don't sum to 1. And it has to be -inf specifically (not a large negative stand-in like -1e9, a common but inexact shortcut) — -inf is the only value guaranteed to exp() to precisely zero.

One convention, one flip point — the bug you actually had today

Worth keeping the before/after honest, because the "before" version wasn't broken — it trained correctly for 30 epochs. The problem was purely where the flip happened.

before — flip hidden inside EncoderCLS, disguised as a feature check
def forward(self, categorical_features, continuous_features, pad_mask_source):
    pad_mask = pad_mask_source == 0        # looks like "check a raw feature for zero"
    cls_col = torch.zeros(batch, 1, ...)    # only correct because of the flip that just happened
    ...
after — pass-through everywhere, flip only in MultiHeadAttention
# EncoderCLS.forward — no flip, no re-derivation
def forward(self, categorical_features, continuous_features, pad_mask):
    cls_col = torch.ones(batch, 1, ...)     # CLS is real -> True, matches the un-flipped convention
    pad_mask = torch.cat([cls_col, pad_mask], dim=1)
    ...

# MultiHeadAttention.forward — the one and only flip
scores = scores.masked_fill(~mask[:, None, None, :], float("-inf"))

Both versions produce the identical final boolean pattern fed into masked_fill — same numeric training result either way. What changed is readability and blast radius: the old version's == 0 looked like it was deriving something from raw data (an anti-pattern in its own right — see Lesson 24's construction pipeline, step 1), and it meant every module downstream of EncoderCLS silently had to know the mask arrived pre-flipped. One flip point means only one function in the entire codebase ever needs to think about which convention masked_fill wants.

⚠ Anti-pattern — deriving padding from a feature's value

Checking feature == 0 to guess "is this padding" is fragile the moment that feature is a normalized, real-valued signal (a z-scored age can legitimately land on exactly 0.0 at a real position). Always derive the mask from actual sequence lengths, computed before padding — never from whether a downstream feature happens to look like zero.

Shape mechanics — a 2D mask reaching into 4D scores

The mask is (batch, seq_len) — one bit per token. Attention scores are (batch, n_heads, seq_len, seq_len) — every query position's score against every key position, per head. Broadcasting bridges the gap, in mask[:, None, None, :]:

shape trace
mask:                  (batch, seq_len)
mask[:, None, None, :]: (batch, 1, 1, seq_len)
scores:                (batch, n_heads, seq_len, seq_len)

Aligning from the right (Lesson 22's broadcasting rule): the last axis (seq_len) matches exactly — "which key positions are blocked." The two inserted size-1 axes stretch to n_heads and the query's own seq_len — meaning the identical padding pattern applies to every head and every query row, which is exactly correct: padding is a property of the sequence, not of which head or which query token is doing the looking.

Where else masking silently matters

Attention is the main place, but not the only one in general: any operation that aggregates across the sequence axis needs to know about padding. EncoderCLS sidesteps this cleanly — CLS pooling means the model learns to ignore padding entirely through masked attention, so no second, separate masked-reduction step is needed anywhere else in the model.

the gotcha this avoids
# if pooling were mean instead of CLS:
x.mean(dim=1)              # WRONG -- divides by the PADDED length, silently diluted by zeros
(x * mask.unsqueeze(-1)).sum(dim=1) / lengths.unsqueeze(-1)   # correct, but now a second place to get right

This is a real reason CLS-style pooling is preferred over mean-pooling in practice: it pushes the entire masking responsibility into attention — which you've already gotten right, once — rather than requiring a second, independent masked-reduction implementation to also get right.

Glossary

Padding mask
Blocks attention to padding positions. Same blocked columns for every query row — padding is a property of the sequence, not of who's attending.
Causal mask
Blocks attention to future positions. Different blocked cells per row — token i can see positions 0..i only. Needed by decoders, not by bidirectional encoders like EncoderCLS.
Convention flip point
The single location in a codebase where a boolean mask's meaning (True=real vs. True=PAD) is allowed to invert. Should be exactly one — inside the attention module, right before masked_fill — never scattered across multiple layers.
Masked pooling
Any sequence-aggregating operation (mean, sum) that must explicitly account for padding, since it isn't protected by attention's own masking the way CLS pooling is.

Checklist

  • A mask is a boolean tensor derived from real sequence lengths — never from checking whether a feature happens to equal a sentinel value.
  • -inf before softmax, not after — exp(-inf)=0 makes masked weights vanish and the rest renormalize automatically.
  • Pick exactly one convention (True=real or True=PAD), document it once, and never let it silently flip more than once across the whole pipeline.
  • A 2D (batch, seq_len) mask reaches 4D attention scores via mask[:, None, None, :] — the same pattern applies to every head and every query row.
  • Structural tokens (CLS, and any future SOS/EOS) get their mask entry added exactly where they themselves get added to the sequence — never earlier.
  • Padding mask ≠ causal mask — mechanically identical (masked_fill + -inf), but blocking different cells; both can stack on the same score matrix.
  • Any non-attention pooling across the sequence axis (mean, sum) needs its own explicit masking — CLS pooling is one of the reasons it's preferred, since it avoids a second place to get this right.
