Study Curriculum

A Study on Transformer

Understanding transformer architecture inside out — not as a language model, but as a general sequence-processing pattern applied to insurance customer data. Twenty-three lessons, most grounded in the actual code in this repo, covering two examples of the pattern applied outside insurance/NLP entirely, a multi-task extension of the encoder project, the real-world model (BERT) behind the CLS trick studied along the way, loss functions beyond plain MSE, how to read — and act on — whether any of it actually worked, where a target value actually comes from, a runnable proof of the guarantee that makes shift-by-one work at all, four ways to interrogate a model after it's already trained, a final synthesis that combines all four into one real answer, the tensor manipulation mechanics every earlier lesson used without stopping to name, and a full derivation of RoPE — the rotation math, not just the intuition.

How to use this

Read the lessons in order the first time — each one builds on the last. After that, use the pill nav above to jump straight to whatever you're rusty on. Every lesson has a Files to open box pointing at the real source in this repo — the code shown is copied verbatim, so you can read the lesson side-by-side with the file in your editor.

  • lesson 12 (Asymmetric Losses) also has no source file — none of the applied projects need it yet, but it generalizes to any regression head in lessons 6, 7, or 10
  • lesson 13 (Reading Training Signals) also has no source file — it's a diagnostic skill grounded in a real training run, applicable to every project in this repo
  • lesson 14 (Baselines & Checkpointing) also has no source file — its baseline code references sample_category()/ITEM_IDS_BY_CAT from the same mock-data pattern used in lessons 6, 7, and 10
  • lesson 15 (Explicit vs Derived Targets) is grounded directly in train_insurance.py (lesson 6) and train_insurance_representation_for_claim.py (lesson 7) — no new file, just a contrast between two already-studied ones

  • lesson 17 (Event Attribution) is grounded in sequences_to_multiple_outcomes.ipynb — a separate side-project notebook (2 architectures × 3 fusion strategies), not one of the three train_insurance*.py entry points
  • lesson 18 (Linear Probing) is grounded in the same sequences_to_multiple_outcomes.ipynb as lesson 17 — its probing code sits right alongside the LOEO cells, reusing the same 6 saved checkpoints
  • lesson 19 (Visualizing Representations) is grounded in the same notebook again, plus main.py for the repo's other precedent of UMAP usage (on contrastive embeddings, a different target than this lesson's item-embedding and pooled-representation plots)
  • lesson 20 (CKA) is grounded in the same notebook once more — its representation extraction is build_probe_dataset from lesson 18, reused unchanged across all 6 configs
  • lesson 21 (Final Synthesis) merges lessons 18 and 20's own dataframes/matrices with a fresh per-checkpoint metrics pull — no new extraction code, just combining what already existed
  • lesson 22 (Tensor Manipulation) is grounded in attention.ipynb — a separate from-scratch attention build outside the lessons/insurance codebase entirely — plus callbacks to package/encoder_block.py's RoPE broadcasting and sequences_to_multiple_outcomes.ipynb's fancy indexing
  • lesson 23 (RoPE, End to End) walks package/encoder_block.py's RoPE class line by line — the same class Lesson 1 introduced, now derived in full instead of just demonstrated
